# Promotions API — інструкція з використання

Цей документ пояснює, як працювати з акціями через API Foxtrot Store Backend: переглядати список активних акцій, отримувати акцію за ID або `slug`, створювати й редагувати акції, призначати товари, налаштовувати знижки, деактивувати та відновлювати акції, а також завантажувати три окремі зображення акції: банер, зображення картки та основне зображення сторінки акції.

## Перед початком

У прикладах `{{baseUrl}}` означає адресу запущеного API, наприклад `https://localhost:7001`. Порт наведено лише як приклад — використовуйте адресу, яку показує застосунок під час запуску.

Для адміністративних операцій потрібен JWT-токен користувача з роллю `Admin`. Отримайте його через наявний у проєкті API авторизації.

У Postman для захищених запитів передавайте заголовок:

```http
Authorization: Bearer {{adminToken}}
```

Банер, зображення картки та основне зображення завантажуються окремими запитами через `multipart/form-data`. Їх не потрібно передавати в JSON під час створення або редагування акції.

## Короткий список запитів

| Метод | URL | Для чого |
|---|---|---|
| `GET` | `/api/promotions` | Отримати список активних акцій |
| `GET` | `/api/promotions/{id}` | Отримати акцію за ID |
| `GET` | `/api/promotions/slug/{slug}` | Отримати акцію за `slug` |
| `GET` | `/api/promotions/images/{imageKey}` | Отримати файл зображення акції |
| `GET` | `/api/promotions/admin` | Отримати всі акції, включно з неактивними — потрібен `Admin` |
| `GET` | `/api/promotions/admin/{id}` | Отримати акцію для адміністрування — потрібен `Admin` |
| `POST` | `/api/promotions` | Створити акцію — потрібен `Admin` |
| `PUT` | `/api/promotions/{id}` | Оновити акцію — потрібен `Admin` |
| `POST` | `/api/promotions/{id}/image` | Завантажити або замінити основне зображення — потрібен `Admin` |
| `POST` | `/api/promotions/{id}/banner` | Завантажити або замінити банер — потрібен `Admin` |
| `POST` | `/api/promotions/{id}/card-image` | Завантажити або замінити зображення картки — потрібен `Admin` |
| `DELETE` | `/api/promotions/{id}` | Деактивувати акцію — потрібен `Admin` |
| `POST` | `/api/promotions/{id}/restore` | Відновити акцію — потрібен `Admin` |

## 1. Перегляд акцій

### Список активних акцій

```http
GET {{baseUrl}}/api/promotions
```

Запит повертає акції, які:

- мають `IsActive = true`;
- уже досягли дати початку, якщо її задано;
- ще не досягли дати завершення, якщо її задано.

Акції сортуються за `SortOrder`, а потім за назвою `Title`.

Приклад структури відповіді (значення наведено для ілюстрації):

```json
{
  "status": {
    "isOk": true,
    "code": 200,
    "message": "OK"
  },
  "meta": {
    "apiName": "Promotions",
    "dataType": "application/json",
    "manipulations": ["GET", "POST", "PUT", "DELETE"]
  },
  "data": [
    {
      "id": "00000000-0000-0000-0000-000000000001",
      "title": "Autumn Sale",
      "slug": "autumn-sale",
      "bannerImageUrl": "/api/promotions/images/a1b2c3d4e5f678901234567890abcdef.webp",
      "cardImageUrl": "/api/promotions/images/b1b2c3d4e5f678901234567890abcdef.webp",
      "sortOrder": 1,
      "discountType": "Percentage",
      "discountValue": 15,
      "productIds": [
        "00000000-0000-0000-0000-000000000002"
      ]
    }
  ]
}
```

`bannerImageUrl` містить посилання на банер для великого рекламного блоку, а `cardImageUrl` — посилання на зображення картки в розділі «Актуальні пропозиції». Якщо відповідне зображення не задано, поле буде `null`. Для значень із зовнішньою URL-адресою метод формування посилання залишає її без змін.

`imageUrl` використовується в детальній інформації про акцію; воно повертається endpoint-ами отримання акції за ID або `slug`, а також адміністративними endpoint-ами. У відповіді списку `GET /api/promotions` поля `imageUrl` немає.

`discountType` визначає тип знижки, а `discountValue` — її величину. Якщо знижку не налаштовано, обидва значення будуть `null`.

`productIds` — список ID товарів, пов'язаних з акцією. Порожній список означає, що до акції не прив'язано товарів.

### Отримати акцію за ID

```http
GET {{baseUrl}}/api/promotions/{{promotionId}}
```

`promotionId` — GUID акції, який повертає API.

Успішна відповідь містить детальну інформацію про акцію в полі `data`, зокрема опис, усі три поля зображень (`bannerImageUrl`, `cardImageUrl` та `imageUrl`), дати дії, тип і значення знижки та список пов'язаних товарів.

Якщо акція не існує, деактивована або перебуває за межами періоду дії, повертається `404 Not Found`.

### Отримати акцію за slug

```http
GET {{baseUrl}}/api/promotions/slug/autumn-sale
```

`slug` — адресне ім'я акції. У запитах створення й оновлення воно має вже відповідати шаблону з малих латинських літер, цифр і дефісів: великі літери та пробіли на початку або в кінці не пройдуть перевірку DTO. Після валідації значення додатково обрізається та переводиться в нижній регістр перед збереженням.

Для порожнього `slug` або рядка довшого за 200 символів endpoint повертає `400 Bad Request`. Якщо акції з таким `slug` немає або вона недоступна для публічного перегляду, повертається `404 Not Found`.

### Отримати деталі акції для адміністратора

```http
GET {{baseUrl}}/api/promotions/admin/{{promotionId}}
Authorization: Bearer {{adminToken}}
```

Цей endpoint повертає деталі акції за її ID, навіть якщо вона деактивована або термін її дії завершився.

Відповідь містить адміністративні поля: `isActive`, `sortOrder`, `createdAt`, `updatedAt`, налаштування знижки, пов'язані товари та всі три поля зображень (`bannerImageUrl`, `cardImageUrl` та `imageUrl`).

### Отримати всі акції для адміністратора

```http
GET {{baseUrl}}/api/promotions/admin
Authorization: Bearer {{adminToken}}
```

Endpoint повертає всі акції без фільтра за активністю та датами. Результат сортується за `SortOrder`, а потім за `Title`.

Це дає змогу адміністратору переглядати як поточні акції, так і неактивні або ті, термін дії яких завершився.

## 2. Створити акцію

Потрібен токен адміністратора.

```http
POST {{baseUrl}}/api/promotions
Authorization: Bearer {{adminToken}}
Content-Type: application/json
```

Приклад тіла запиту:

```json
{
  "title": "Autumn Sale",
  "slug": "autumn-sale",
  "description": "Спеціальні пропозиції на вибрані товари",
  "discountType": "Percentage",
  "discountValue": 15,
  "productIds": [
    "00000000-0000-0000-0000-000000000002"
  ],
  "startDate": "2026-10-01T00:00:00Z",
  "endDate": "2026-11-01T00:00:00Z",
  "isActive": true,
  "sortOrder": 1
}
```

У прикладі використано демонстраційний ID товару. У реальному запиті передавайте ID наявних активних товарів.

### Правила для полів

| Поле | Правила |
|---|---|
| `title` | Обов'язкове, максимум 200 символів |
| `slug` | Обов'язкове, максимум 200 символів, унікальне |
| `description` | Необов'язковий опис, максимум 2000 символів |
| `discountType` | Необов'язковий тип знижки: `Percentage` або `FixedAmount` |
| `discountValue` | Необов'язкова величина знижки; має задаватися разом із `discountType` |
| `productIds` | Список GUID товарів, прив'язаних до акції |
| `startDate` | Необов'язкова дата початку дії |
| `endDate` | Необов'язкова дата завершення дії |
| `isActive` | Ознака активності; за замовчуванням `true` |
| `sortOrder` | Числовий порядок відображення |

Для `slug` дозволені лише малі латинські літери, цифри та одиночні дефіси між частинами; значення має починатися й закінчуватися літерою або цифрою. Пробіли, великі літери, дефіс на початку/в кінці та послідовні дефіси не проходять DTO-валідацію. Приклади правильних значень: `autumn-sale`, `phones-2026`, `sale15`.

Значення `slug` унікальне серед усіх акцій, включно з деактивованими. Тому `slug` неактивної акції не можна використати повторно, доки відповідний запис залишається в базі.

### Налаштування знижки

Підтримуються два типи знижок:

- `Percentage` — знижка у відсотках;
- `FixedAmount` — знижка у фіксованій грошовій сумі.

Правила перевірки:

- `discountType` і `discountValue` потрібно передавати разом або не передавати обидва;
- для `Percentage` значення має бути більшим за `0` і не більшим за `100`;
- для `FixedAmount` значення має бути більшим за `0`;
- значення знижки може містити не більше двох знаків після десяткової крапки.

Наприклад, `discountType: "Percentage"` і `discountValue: 15` означають знижку 15%. Значення `discountType: "FixedAmount"` і `discountValue: 200` означають зменшення ціни на 200 грошових одиниць у валюті каталогу.

Якщо обидва поля знижки дорівнюють `null`, акція може використовуватися як інформаційна або рекламна кампанія без цінової знижки.

### Дати дії

`startDate` та `endDate` необов'язкові. Якщо одну з дат не задано, відповідне обмеження не застосовується.

Дата завершення не може бути ранішою за дату початку. Якщо це правило порушено, API повертає `400 Bad Request`.

Публічна доступність акції додатково залежить від `isActive` та поточної дати й часу на сервері.

### Прив'язка товарів

`productIds` визначає товари, до яких належить акція.

- Кожен ID має відповідати наявному активному товару.
- Повторення одного ID в списку заборонено.
- Якщо список порожній, акція створюється без прив'язаних товарів.

Якщо один або кілька товарів відсутні або деактивовані, запит повертає `400 Bad Request`.

Банер, зображення картки та основне зображення не передаються під час створення: для них використовуються окремі endpoints.

Успішне створення повертає `201 Created` і створену акцію в полі `data`.

Якщо `slug` уже зайнятий, повертається `409 Conflict`. Помилки валідації запиту повертають `400 Bad Request`.

## 3. Оновити акцію

Потрібен токен адміністратора.

```http
PUT {{baseUrl}}/api/promotions/{{promotionId}}
Authorization: Bearer {{adminToken}}
Content-Type: application/json
```

Приклад тіла запиту:

```json
{
  "title": "Autumn Sale Updated",
  "slug": "autumn-sale-updated",
  "description": "Оновлена акційна пропозиція",
  "discountType": "Percentage",
  "discountValue": 20,
  "productIds": [
    "00000000-0000-0000-0000-000000000002",
    "00000000-0000-0000-0000-000000000003"
  ],
  "startDate": "2026-10-01T00:00:00Z",
  "endDate": "2026-11-15T00:00:00Z",
  "isActive": true,
  "sortOrder": 2
}
```

Під час оновлення застосовуються ті самі правила перевірки полів, дат, `slug`, знижки та товарів, що й під час створення.

Поле `isActive` потрібно передавати в запиті оновлення.

`productIds` визначає повний актуальний список товарів акції. Зв'язки з товарами, ID яких відсутні в запиті, видаляються; нові зв'язки додаються. Тому передавайте повний список товарів, які мають залишитися в акції.

Основне зображення, банер і зображення картки через `PUT` не змінюються. Для кожного з них передбачено окремий endpoint завантаження.

Очікувані відповіді:

- `200 OK` — акцію оновлено;
- `400 Bad Request` — помилка валідації;
- `404 Not Found` — акції з таким ID немає;
- `409 Conflict` — `slug` уже використовується або виникла інша конфліктна ситуація, яку обробляє API.

Адміністратор може редагувати деактивовану акцію за її ID. Звичайне оновлення не активує її повторно, якщо `isActive` передано як `false`.

## 4. Деактивувати та відновити акцію

Акції деактивуються м'яко: запис залишається в базі, а значення `IsActive` змінюється на `false`. Це дає змогу згодом відновити акцію або переглянути її в адміністративному списку.

### Деактивація

```http
DELETE {{baseUrl}}/api/promotions/{{promotionId}}
Authorization: Bearer {{adminToken}}
```

Успішна відповідь має статус `200 OK` і повідомлення:

```json
{
  "message": "Promotion deactivated successfully."
}
```

Якщо акції з таким ID немає або вона вже деактивована, повертається `404 Not Found`.

### Відновлення

```http
POST {{baseUrl}}/api/promotions/{{promotionId}}/restore
Authorization: Bearer {{adminToken}}
```

Успішна відповідь має статус `200 OK` і повідомлення:

```json
{
  "message": "Promotion restored successfully."
}
```

Якщо акції немає або вона вже активна, повертається `404 Not Found`.

Відновлення встановлює `IsActive = true`, але не скасовує обмеження за датами. Якщо період дії ще не почався або вже завершився, відновлена акція залишатиметься недоступною через публічні endpoints.

## 5. Завантажити або замінити зображення акції

Для всіх трьох endpoint потрібен токен адміністратора. Зображення зберігаються окремо: `imageUrl` — основне зображення сторінки акції, `bannerImageUrl` — банер, `cardImageUrl` — зображення картки «Актуальні пропозиції». Кожен запит замінює лише відповідне зображення.

### Основне зображення сторінки акції

```http
POST {{baseUrl}}/api/promotions/{{promotionId}}/image
Authorization: Bearer {{adminToken}}
```

У Postman:

1. Виберіть метод `POST` та вкажіть URL із реальним `promotionId`.
2. Відкрийте **Body → form-data**.
3. Додайте поле `file`, змініть його тип на **File** і виберіть зображення.
4. Додайте заголовок авторизації та надішліть запит.

Успішна відповідь має приблизно такий вигляд:

```json
{
  "status": {
    "isOk": true,
    "code": 200,
    "message": "OK"
  },
  "meta": {
    "apiName": "PromotionImage",
    "dataType": "application/json",
    "manipulations": ["POST"],
    "links": {
      "parent": "/api/promotions",
      "image": "/api/promotions/images/a1b2c3d4e5f678901234567890abcdef.webp"
    }
  },
  "data": {
    "promotionId": "00000000-0000-0000-0000-000000000001",
    "imageKey": "a1b2c3d4e5f678901234567890abcdef.webp",
    "imageUrl": "/api/promotions/images/a1b2c3d4e5f678901234567890abcdef.webp"
  }
}
```

`imageKey` — ключ збереженого файлу, а `imageUrl` — шлях для перегляду зображення через API.

### Банер акції

```http
POST {{baseUrl}}/api/promotions/{{promotionId}}/banner
Authorization: Bearer {{adminToken}}
```

Запит виконується так само, як завантаження основного зображення: через **Body → form-data** з полем `file` типу **File**.

Успішна відповідь містить `promotionId`, `imageKey` і поле `bannerImageUrl` замість `imageUrl`.

### Зображення картки «Актуальні пропозиції»

```http
POST {{baseUrl}}/api/promotions/{{promotionId}}/card-image
Authorization: Bearer {{adminToken}}
```

Надішліть запит через **Body → form-data** з полем `file` типу **File** так само, як для основного зображення та банера.

Успішна відповідь містить `promotionId`, `imageKey` і поле `cardImageUrl`. Отриманий URL можна використовувати для зображення картки акції у frontend.

Під час повторного завантаження сервер спочатку зберігає новий файл і записує його ключ у базу. Після успішного оновлення він намагається видалити попередній локальний файл. Якщо збереження в базі завершується помилкою, сервер намагається видалити щойно завантажений файл.

Ця логіка однакова для основного зображення, банера та зображення картки. Заміна одного типу зображення не змінює два інші. Попередній файл видаляється лише тоді, коли його ключ відповідає формату локального файлу, який використовує LocalStorage; зовнішні URL не видаляються.

Зображення можна завантажувати для наявної акції, зокрема деактивованої: у методі збереження перевіряється існування акції, а не її активність.

Якщо файл не передано або його розмір дорівнює нулю, повертається `400 Bad Request`. Якщо LocalStorage відхиляє файл через некоректні дані, API також повертає `400 Bad Request`. Якщо акції не існує, повертається `404 Not Found`.

## 6. Отримати файл зображення акції

```http
GET {{baseUrl}}/api/promotions/images/{{imageKey}}
```

Цей endpoint публічний і не потребує токена.

`imageKey` — ключ файлу, який повернув endpoint завантаження. Наприклад:

```text
a1b2c3d4e5f678901234567890abcdef.webp
```

Успішний запит повертає вміст зображення з відповідним MIME-типом, а не JSON.

Для завантаження через LocalStorage підтримуються статичні зображення JPEG, PNG і WEBP. За типовими налаштуваннями максимальний розмір вихідного файлу становить 5 MiB, а розмір зображення обмежений 12 000 000 пікселів; фактичні межі можуть змінюватися через конфігурацію `LocalStorage`. Анімовані зображення не підтримуються.

Підтримуються розширення:

| Розширення | MIME-тип |
|---|---|
| `.jpg` | `image/jpeg` |
| `.png` | `image/png` |
| `.webp` | `image/webp` |

Непідтримуване розширення повертає `400 Bad Request`. Некоректний ключ також може повернути `400 Bad Request`, а якщо файл не знайдено — `404 Not Found`.

`imageUrl`, `bannerImageUrl` та `cardImageUrl` для локально завантажених файлів містять відносні шляхи, наприклад:

```text
/api/promotions/images/a1b2c3d4e5f678901234567890abcdef.webp
```

Якщо frontend працює на іншому домені або порту, перед цим шляхом потрібно додати базову адресу API. Для зовнішніх URL, які були збережені замість локального ключа, використовується сама зовнішня адреса.

## 7. Як застосовуються знижки

Акція може бути пов'язана з кількома товарами через таблицю зв'язків `PromotionProduct`.

Для розрахунку акційної ціни враховуються акції, які:

- активні;
- перебувають у межах заданого періоду дії;
- мають налаштовані `DiscountType` і `DiscountValue`;
- пов'язані з відповідним товаром.

### Розрахунок ціни

Для `Percentage` сума знижки обчислюється у відсотках від початкової ціни товару та округлюється до двох знаків після десяткової крапки.

Для `FixedAmount` від початкової ціни віднімається задана сума.

Знижка не може зменшити ціну нижче нуля. Якщо для товару доступно кілька акцій, вибирається варіант із найменшою кінцевою ціною. Якщо кінцеві ціни однакові, перевага надається акції з меншим `SortOrder`, а далі — за назвою.

У відповідях товарів акційна ціна повертається в полі `activePromotion`. Приклад структури:

```json
{
  "activePromotion": {
    "promotionId": "00000000-0000-0000-0000-000000000001",
    "title": "Autumn Sale",
    "slug": "autumn-sale",
    "discountType": "Percentage",
    "discountValue": 15,
    "originalPrice": 10000,
    "discountAmount": 1500,
    "discountedPrice": 8500
  }
}
```

Значення в прикладі демонстраційні. `originalPrice` — початкова ціна товару, `discountAmount` — обчислена сума знижки, `discountedPrice` — кінцева ціна з урахуванням обраної акції.

Якщо для товару немає відповідної активної акції зі знижкою, `activePromotion` буде `null`.

Розрахунок не змінює базову ціну в полі `Product.Price`. Акційна ціна поки що повертається як частина даних каталогу; окрему перевірку ціни під час оформлення замовлення потрібно реалізувати в майбутньому API кошика та замовлень.

## 8. Типові помилки API

Залежно від endpoint API може повертати такі HTTP-статуси:

| Код | Значення |
|---|---|
| `200 OK` | Запит виконано успішно |
| `201 Created` | Акцію створено |
| `400 Bad Request` | Некоректні дані, параметри або файл |
| `401 Unauthorized` | Відсутній або недійсний токен для захищеного запиту |
| `403 Forbidden` | Користувач не має ролі `Admin` |
| `404 Not Found` | Акцію або файл не знайдено чи акція недоступна через публічний endpoint |
| `409 Conflict` | Конфлікт під час створення або оновлення, наприклад повторний `slug` |
| `500 Internal Server Error` | Непередбачена помилка сервера |

Помилки, які явно обробляються endpoint-ами, зазвичай повертаються в оболонці `RestResponse`. Однак автоматичні помилки валідації від `[ApiController]`, а також відповіді механізму автентифікації й авторизації можуть мати стандартний формат ASP.NET Core, а не `RestResponse`.
