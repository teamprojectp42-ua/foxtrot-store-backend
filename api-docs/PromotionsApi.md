# Promotions API — інструкція з використання

Цей документ описує фактичну роботу API акцій Foxtrot Store Backend: перегляд публічних та адміністративних списків, отримання акції за ID або `slug`, створення й оновлення перекладів, налаштування знижок, прив'язку товарів, деактивацію та відновлення акцій, а також завантаження трьох окремих зображень.

## Перед початком

У прикладах `{{baseUrl}}` — базова адреса запущеного API, наприклад `https://localhost:7001`. Використовуйте адресу та порт, які показує застосунок під час запуску.

Для адміністративних операцій потрібен JWT-токен користувача з роллю `Admin`. У захищених запитах передавайте заголовок:

```http
Authorization: Bearer {{adminToken}}
```

Публічні запити перегляду акцій та отримання файлів зображень не потребують токена.

Назва й опис акції є багатомовними. У запитах створення та оновлення вони передаються не окремими полями `title` і `description`, а всередині масиву `translations`.

## Короткий список запитів

| Метод | URL | Для чого |
|---|---|---|
| `GET` | `/api/promotions` | Отримати список публічно доступних акцій |
| `GET` | `/api/promotions/{id}` | Отримати публічно доступну акцію за ID |
| `GET` | `/api/promotions/slug/{slug}` | Отримати публічно доступну акцію за `slug` |
| `GET` | `/api/promotions/images/{imageKey}` | Отримати файл зображення акції |
| `GET` | `/api/promotions/admin` | Отримати всі акції — потрібен `Admin` |
| `GET` | `/api/promotions/admin/{id}` | Отримати акцію для адміністрування — потрібен `Admin` |
| `POST` | `/api/promotions` | Створити акцію — потрібен `Admin` |
| `PUT` | `/api/promotions/{id}` | Оновити акцію — потрібен `Admin` |
| `POST` | `/api/promotions/{id}/image` | Завантажити або замінити основне зображення — потрібен `Admin` |
| `POST` | `/api/promotions/{id}/banner` | Завантажити або замінити банер — потрібен `Admin` |
| `POST` | `/api/promotions/{id}/card-image` | Завантажити або замінити зображення картки — потрібен `Admin` |
| `DELETE` | `/api/promotions/{id}` | Деактивувати акцію — потрібен `Admin` |
| `POST` | `/api/promotions/{id}/restore` | Відновити акцію — потрібен `Admin` |

Усі адміністративні endpoints цього контролера вимагають саме роль `Admin`.

## 1. Перегляд акцій

### Список публічно доступних акцій

```http
GET {{baseUrl}}/api/promotions
```

Повертаються лише акції, які:

- мають `IsActive = true`;
- уже досягли `StartDate`, якщо дату задано;
- ще не минули `EndDate`, якщо дату задано.

Межі періоду включні: акція доступна, коли `StartDate <= поточний час UTC` і `EndDate >= поточний час UTC`. Якщо одну з дат не задано, відповідне обмеження не застосовується.

Результат сортується за `SortOrder` за зростанням, а потім за локалізованим `Title` без урахування регістру.

Приклад структури відповіді:

```json
{
  "status": {
    "isOk": true,
    "code": 200,
    "message": "OK"
  },
  "meta": {
    "apiName": "Promotions",
    "dataType": "application/json",
    "manipulations": ["GET", "POST", "PUT", "DELETE"]
  },
  "data": [
    {
      "id": "00000000-0000-0000-0000-000000000001",
      "title": "Осінній розпродаж",
      "slug": "autumn-sale",
      "discountType": "Percentage",
      "discountValue": 15,
      "productIds": [
        "00000000-0000-0000-0000-000000000002"
      ],
      "bannerImageUrl": "/api/promotions/images/a1b2c3d4e5f678901234567890abcdef.webp",
      "cardImageUrl": "/api/promotions/images/b1b2c3d4e5f678901234567890abcdef.webp",
      "sortOrder": 1
    }
  ]
}
```

Це приклад структури, а не фактичні дані. Поле `serverTime` з `RestMeta` у прикладі опущене: його фактичне значення генерується сервером для кожної відповіді.

`GET /api/promotions` повертає `PromotionDto`. У ньому є `bannerImageUrl` і `cardImageUrl`, але немає `imageUrl`, `description`, `startDate` та `endDate`. Основне зображення сторінки акції (`imageUrl`) доступне в детальних та адміністративних відповідях.

Якщо зображення не задано, відповідне поле повертається як `null`. Локальний ключ зображення, що відповідає формату LocalStorage, перетворюється на шлях `/api/promotions/images/{imageKey}`. Інше збережене значення повертається без такої трансформації.

Якщо знижку не налаштовано, `discountType` і `discountValue` дорівнюють `null`. `productIds` містить ID пов'язаних товарів; порожній масив означає, що товарів не прив'язано.

### Отримати акцію за ID

```http
GET {{baseUrl}}/api/promotions/{{promotionId}}
```

`promotionId` — GUID акції.

Успішна відповідь містить `PromotionDetailsDto`: локалізовані `title` і `description`, `slug`, налаштування знижки, `productIds`, усі три поля зображень (`bannerImageUrl`, `cardImageUrl`, `imageUrl`), а також `startDate` і `endDate`.

Якщо акції не існує, вона деактивована або перебуває поза періодом дії, повертається `404 Not Found`.

### Отримати акцію за slug

```http
GET {{baseUrl}}/api/promotions/slug/autumn-sale
```

Endpoint застосовує такі перевірки:

- порожній або такий, що складається з пробілів, `slug` повертає `400 Bad Request`;
- довжина понад 200 символів повертає `400 Bad Request`;
- перед пошуком значення обрізається по краях і переводиться в нижній регістр.

На відміну від DTO створення й оновлення, цей endpoint не застосовує до вхідного рядка регулярний вираз slug. Наприклад, регістр і пробіли по краях нормалізуються перед пошуком. Якщо відповідної публічно доступної акції немає, повертається `404 Not Found`.

### Адміністративний список

```http
GET {{baseUrl}}/api/promotions/admin
Authorization: Bearer {{adminToken}}
```

Endpoint повертає всі акції без фільтра за `IsActive` та датами. Список містить також неактивні акції та акції з періодом дії, що завершився. Повертається `PromotionAdminDto`, включно з усіма збереженими перекладами, трьома зображеннями, датами, `isActive`, `sortOrder`, `createdAt` і `updatedAt`.

Результат сортується за `SortOrder`, а потім за локалізованим `Title`. Пагінації в цьому endpoint немає.

### Отримати адміністративні деталі акції

```http
GET {{baseUrl}}/api/promotions/admin/{{promotionId}}
Authorization: Bearer {{adminToken}}
```

Повертає акцію за ID незалежно від її активності та періоду дії. Якщо запису з таким ID немає, повертається `404 Not Found`.

Адміністративна DTO містить локалізовані `title` і `description`, повний масив `translations`, налаштування знижки, список товарів, усі три зображення, дати, стан активності, порядок сортування та часові мітки.

## 2. Створити акцію

Потрібен токен адміністратора.

```http
POST {{baseUrl}}/api/promotions
Authorization: Bearer {{adminToken}}
Content-Type: application/json
```

Приклад тіла запиту:

```json
{
  "slug": "autumn-sale",
  "translations": [
    {
      "cultureCode": "uk-UA",
      "title": "Осінній розпродаж",
      "description": "Спеціальні пропозиції на вибрані товари"
    },
    {
      "cultureCode": "en-US",
      "title": "Autumn Sale",
      "description": "Special offers on selected products"
    }
  ],
  "discountType": "Percentage",
  "discountValue": 15,
  "productIds": [
    "00000000-0000-0000-0000-000000000002"
  ],
  "startDate": "2026-11-15T00:00:00Z",
  "endDate": "2026-12-31T23:59:59Z",
  "isActive": true,
  "sortOrder": 1
}
```

ID товару в прикладі демонстраційний. У реальному запиті передавайте ID наявного активного товару.

### Поля запиту

| Поле | Правила |
|---|---|
| `slug` | Обов'язкове, максимум 200 символів; лише малі латинські літери, цифри й одиночні дефіси між частинами |
| `translations` | Обов'язковий масив щонайменше з одним перекладом; під час створення обов'язково має містити `uk-UA` |
| `translations[].cultureCode` | Обов'язковий код культури, максимум 10 символів; повторення кодів у масиві заборонені без урахування регістру |
| `translations[].title` | Обов'язкова назва перекладу, від 1 до 200 символів після обрізання пробілів |
| `translations[].description` | Необов'язковий опис перекладу, максимум 2000 символів |
| `discountType` | Необов'язковий тип знижки: `Percentage` або `FixedAmount` |
| `discountValue` | Необов'язкова величина знижки; має задаватися разом із `discountType` |
| `productIds` | Список GUID активних товарів; за замовчуванням порожній масив, явне значення `null` не допускається логікою DataAccessor |
| `startDate` | Необов'язкова дата початку дії |
| `endDate` | Необов'язкова дата завершення дії |
| `isActive` | Ознака активності; за замовчуванням `true` |
| `sortOrder` | Числовий порядок відображення; за замовчуванням `0` |

### Правила slug

Для `slug` дозволені лише малі латинські літери `a-z`, цифри `0-9` та одиночні дефіси між частинами. Значення має починатися й закінчуватися літерою або цифрою.

Правильні приклади:

- `autumn-sale`
- `phones-2026`
- `sale15`

Пробіли, великі літери, дефіс на початку або в кінці та послідовні дефіси не проходять DTO-валідацію.

`slug` унікальний серед усіх акцій, включно з деактивованими. Деактивація не звільняє slug для повторного використання.

### Переклади

Кожен елемент `translations` має містити `cultureCode` і `title`; `description` необов'язковий. Значення назви та опису обрізаються від крайніх пробілів. Після нормалізації порожня назва не допускається.

Під час створення обов'язково передати переклад `uk-UA`. Це також є резервною локаллю для публічних відповідей, якщо перекладу поточної культури немає.

Одна культура може бути в масиві лише один раз. Перевірка повторів не враховує регістр, тому `uk-UA` та `UK-ua` в одному запиті вважаються дублікатом.

У відповідях поле `title` вибирається за поточною `CurrentUICulture`; якщо перекладу немає, використовується `uk-UA`. Для `description` застосовується така сама послідовність, але якщо опис відсутній в обох перекладах, повертається `null`.

### Налаштування знижки

Підтримуються два типи:

- `Percentage` — знижка у відсотках від початкової ціни товару;
- `FixedAmount` — знижка у фіксованій грошовій сумі у валюті каталогу.

Правила перевірки:

- `discountType` і `discountValue` потрібно передавати разом або не передавати обидва;
- `discountType` потрібно передавати JSON-рядком: `"Percentage"` або `"FixedAmount"` (регістр літер не має значення); числові значення `1`, `2` та рядки `"1"`, `"2"` не приймаються й повертають `400 Bad Request`;
- для `Percentage` значення має бути більшим за `0` і не більшим за `100`;
- для `FixedAmount` значення має бути більшим за `0`;
- значення може містити не більше двох знаків після десяткової крапки.

Приклади:

```json
{
  "discountType": "Percentage",
  "discountValue": 15
}
```

```json
{
  "discountType": "FixedAmount",
  "discountValue": 200
}
```

Якщо обидва поля дорівнюють `null`, акція може бути інформаційною кампанією без цінової знижки.

Для `discountType` у вхідних DTO створення й оновлення використовується окремий строгий JSON-конвертер. Він приймає лише рядкові назви `Percentage` і `FixedAmount` без урахування регістру. `null` також допускається, оскільки поле необов'язкове. Числа (`1`, `2`), числові рядки (`"1"`, `"2"`), порожні рядки та невідомі назви відхиляються під час десеріалізації й повертають `400 Bad Request` через механізм валідації `[ApiController]`.

У відповідях API `discountType` також серіалізується як рядкова назва enum.

### Дати дії

`startDate` та `endDate` необов'язкові. Якщо дату не задано, відповідна межа періоду не застосовується. `endDate` не може бути ранішою за `startDate`; порушення повертає `400 Bad Request`.

Порівняння періоду з поточним часом виконується через `DateTime.UtcNow`. У запитах рекомендується передавати дати в ISO 8601 з часовим поясом UTC, наприклад `2026-10-01T00:00:00Z`.

### Прив'язка товарів

`productIds` визначає товари, на які поширюється акція.

- Кожен ID має відповідати наявному активному товару.
- Повторення одного ID у списку заборонено.
- Порожній список дозволений: акція створюється без прив'язаних товарів.
- Якщо один або кілька товарів відсутні чи неактивні, повертається `400 Bad Request`.

Зображення не передаються під час створення. Для кожного типу зображення є окремий endpoint.

Успішне створення повертає `201 Created` і `PromotionAdminDto` у полі `data`. Якщо slug уже використовується, API повертає `409 Conflict`; помилки валідації — `400 Bad Request`.

## 3. Оновити акцію

Потрібен токен адміністратора.

```http
PUT {{baseUrl}}/api/promotions/{{promotionId}}
Authorization: Bearer {{adminToken}}
Content-Type: application/json
```

Приклад:

```json
{
  "slug": "autumn-sale-updated",
  "translations": [
    {
      "cultureCode": "uk-UA",
      "title": "Оновлений осінній розпродаж",
      "description": "Оновлена акційна пропозиція"
    },
    {
      "cultureCode": "en-US",
      "title": "Updated Autumn Sale",
      "description": "Updated special offer"
    }
  ],
  "discountType": "Percentage",
  "discountValue": 20,
  "productIds": [
    "00000000-0000-0000-0000-000000000002",
    "00000000-0000-0000-0000-000000000003"
  ],
  "startDate": "2026-10-01T00:00:00Z",
  "endDate": "2026-11-15T00:00:00Z",
  "isActive": true,
  "sortOrder": 2
}
```

Застосовуються ті самі правила перевірки `slug`, перекладів, знижки, дат і товарів, що й під час створення. На відміну від створення, під час оновлення достатньо передати хоча б один переклад: `uk-UA` у запиті не є обов'язковим.

`isActive` потрібно передавати обов'язково. Якщо передати `false`, акція залишиться деактивованою; звичайне оновлення не активує її автоматично.

### Що відбувається, якщо поле не передано в PUT

`PUT` не працює як часткове оновлення. Для необов'язкових полів відсутнє значення десеріалізується як `null` або залишається значенням ініціалізації DTO, після чого записується в акцію:

- якщо `startDate` або `endDate` не передано, відповідна дата очищається (`null`);
- якщо не передано обидва поля `discountType` і `discountValue`, знижка очищається;
- якщо передано лише одне з двох полів знижки, API повертає `400 Bad Request`;
- якщо `productIds` не передано, використовується порожній список і всі зв'язки з товарами видаляються;
- якщо `sortOrder` не передано, він скидається до `0`.

`slug`, `isActive` і `translations` потрібно передавати в кожному запиті оновлення. `translations` має містити щонайменше один елемент. Водночас переклади окремих культур, пропущені всередині переданого масиву, не видаляються — див. наступний розділ.

Тому під час оновлення надсилайте всі значення, які мають залишитися в акції, навіть якщо змінюєте лише одне поле. Зображення через `PUT` не змінюються.

### Як синхронізуються переклади

Оновлення перекладів має поведінку upsert:

- якщо переданий `cultureCode` уже існує, його `title` та `description` оновлюються;
- якщо такого `cultureCode` ще немає, переклад додається;
- переклади, які є в базі, але відсутні в запиті, **не видаляються**.

Отже, `translations` у запиті оновлення не є повною заміною набору перекладів. Цей endpoint не має операції видалення окремого перекладу.

### Як синхронізуються товари

`productIds` задає повний актуальний список товарів акції:

- зв'язки з товарами, ID яких відсутні в запиті, видаляються;
- нові зв'язки додаються;
- уже наявні зв'язки зберігаються.

Тому передавайте повний список товарів, які мають залишитися в акції. Порожній масив видаляє всі зв'язки з товарами.

Основне зображення, банер і зображення картки через `PUT` не змінюються. Для них використовуються окремі endpoints завантаження.

Очікувані відповіді:

- `200 OK` — акцію оновлено;
- `400 Bad Request` — помилка валідації;
- `404 Not Found` — акції з таким ID немає (за умови, що тіло запиту пройшло попередню валідацію);
- `409 Conflict` — slug уже використовується або виникла інша конфліктна ситуація, яку обробляє API.

Адміністратор може редагувати деактивовану акцію за її ID.

## 4. Деактивувати та відновити акцію

Деактивація є м'якою: запис залишається в базі, а `IsActive` змінюється на `false`. Пов'язані переклади, зображення та зв'язки з товарами не видаляються.

### Деактивація

```http
DELETE {{baseUrl}}/api/promotions/{{promotionId}}
Authorization: Bearer {{adminToken}}
```

Успішна відповідь має статус `200 OK`. Повідомлення знаходиться всередині `data` стандартної оболонки `RestResponse`. Поле `serverTime` у прикладі опущене, оскільки його значення генерується сервером:

```json
{
  "status": {
    "isOk": true,
    "code": 200,
    "message": "OK"
  },
  "meta": {
    "apiName": "Promotions",
    "dataType": "application/json",
    "manipulations": ["GET", "POST", "PUT", "DELETE"]
  },
  "data": {
    "message": "Promotion deactivated successfully."
  }
}
```

Якщо акції з таким ID немає або вона вже деактивована, повертається `404 Not Found`.

### Відновлення

```http
POST {{baseUrl}}/api/promotions/{{promotionId}}/restore
Authorization: Bearer {{adminToken}}
```

Успішна відповідь також використовує оболонку `RestResponse`:

```json
{
  "status": {
    "isOk": true,
    "code": 200,
    "message": "OK"
  },
  "meta": {
    "apiName": "Promotions",
    "dataType": "application/json",
    "manipulations": ["GET", "POST", "PUT", "DELETE"]
  },
  "data": {
    "message": "Promotion restored successfully."
  }
}
```

Якщо акції немає або вона вже активна, повертається `404 Not Found`.

Відновлення встановлює `IsActive = true`, але не змінює `StartDate` і `EndDate`. Тому відновлена акція не з'явиться в публічних endpoints, доки не почнеться її період дії або якщо він уже завершився.

## 5. Завантажити або замінити зображення

Для всіх трьох endpoints потрібен токен `Admin`. Зображення зберігаються окремо:

| Поле | Призначення | Endpoint |
|---|---|---|
| `imageUrl` | Основне зображення сторінки акції | `POST /api/promotions/{id}/image` |
| `bannerImageUrl` | Банер акції | `POST /api/promotions/{id}/banner` |
| `cardImageUrl` | Зображення картки в «Актуальних пропозиціях» | `POST /api/promotions/{id}/card-image` |

Кожен запит замінює лише відповідне зображення та не змінює два інші.

### Приклад завантаження

```http
POST {{baseUrl}}/api/promotions/{{promotionId}}/image
Authorization: Bearer {{adminToken}}
```

У Postman:

1. Виберіть **Body → form-data**.
2. Додайте поле з назвою `file`.
3. Змініть тип поля на **File** і виберіть зображення.
4. Додайте Bearer-токен та надішліть запит.

Для банера та зображення картки використовується той самий формат запиту, але інший URL.

### Успішна відповідь

Для основного зображення відповідь має такий вигляд:

```json
{
  "status": {
    "isOk": true,
    "code": 200,
    "message": "OK"
  },
  "meta": {
    "apiName": "PromotionImage",
    "dataType": "application/json",
    "manipulations": ["POST"],
    "links": {
      "parent": "/api/promotions",
      "image": "/api/promotions/images/a1b2c3d4e5f678901234567890abcdef.webp"
    }
  },
  "data": {
    "promotionId": "00000000-0000-0000-0000-000000000001",
    "imageKey": "a1b2c3d4e5f678901234567890abcdef.webp",
    "imageUrl": "/api/promotions/images/a1b2c3d4e5f678901234567890abcdef.webp"
  }
}
```

Для банера поле `imageUrl` у `data` замінюється на `bannerImageUrl`, а для зображення картки — на `cardImageUrl`.

`imageKey` — ключ збереженого файлу. `imageUrl`, `bannerImageUrl` або `cardImageUrl` — шлях для отримання цього файлу через API.

### Заміна та видалення попереднього файлу

Під час заміни сервер:

1. зберігає новий файл у LocalStorage;
2. записує новий ключ у відповідне поле акції;
3. після успішного збереження в базі намагається видалити попередній локальний файл.

Якщо акції не існує або оновлення бази завершується помилкою, сервер намагається видалити щойно завантажений файл. Помилка такого очищення не приховує початковий результат або виняток, а записується в лог.

Попередній файл видаляється лише тоді, коли його ключ відповідає формату локального ключа: GUID без роздільників (`N`) із розширенням `.jpg`, `.png` або `.webp`. Зовнішні URL та інші значення не видаляються.

Зображення можна завантажувати для наявної деактивованої акції: під час збереження перевіряється існування запису, а не `IsActive`.

### Обмеження файлів

За типовими налаштуваннями LocalStorage:

- підтримуються статичні JPEG (`.jpg`), PNG (`.png`) і WEBP (`.webp`);
- максимальний розмір файлу — 5 MiB;
- максимальний розмір зображення — 12 000 000 пікселів;
- анімовані зображення не підтримуються.

Фактичні обмеження залежать від конфігурації `LocalStorage`.

Якщо файл не передано або його розмір дорівнює нулю, endpoint повертає `400 Bad Request`. Якщо LocalStorage відхиляє файл із `InvalidDataException`, API також повертає `400 Bad Request`. Якщо акції не існує, повертається `404 Not Found`.

## 6. Отримати файл зображення

```http
GET {{baseUrl}}/api/promotions/images/{{imageKey}}
```

Endpoint публічний і не потребує токена. Він повертає вміст зображення з MIME-типом, визначеним за розширенням файлу, а не JSON.

Підтримуються такі розширення:

| Розширення | MIME-тип |
|---|---|
| `.jpg` | `image/jpeg` |
| `.png` | `image/png` |
| `.webp` | `image/webp` |

Непідтримуване розширення повертає `400 Bad Request`. Якщо LocalStorage відхиляє ключ як некоректний через `ArgumentException`, повертається `400 Bad Request`. Якщо файл із коректним типом не знайдено, повертається `404 Not Found`.

Локальні ключі зображень формуються у вигляді GUID без роздільників та розширення, наприклад:

```text
a1b2c3d4e5f678901234567890abcdef.webp
```

Для локально збережених зображень поля `imageUrl`, `bannerImageUrl` та `cardImageUrl` містять відносний шлях:

```text
/api/promotions/images/a1b2c3d4e5f678901234567890abcdef.webp
```

Якщо frontend працює на іншому домені або порту, до відносного шляху потрібно додати базову адресу API. Значення, які не розпізнаються як локальний ключ очікуваного формату, повертаються без трансформації; зокрема, зовнішні URL залишаються без змін.

## 7. Як застосовуються знижки

Акція може бути пов'язана з кількома товарами через таблицю `PromotionProduct`.

Для розрахунку акційної ціни враховуються акції, які:

- активні (`IsActive = true`);
- перебувають у межах заданого періоду дії;
- мають одночасно налаштовані `DiscountType` і `DiscountValue`;
- пов'язані з відповідним товаром.

Акції без налаштованої знижки можуть використовуватися як інформаційні кампанії, але не створюють `activePromotion` із ціною.

### Розрахунок ціни

Для `Percentage` сума знижки обчислюється від початкової ціни товару та округлюється до двох знаків після десяткової крапки за правилом `MidpointRounding.AwayFromZero`.

Для `FixedAmount` від початкової ціни віднімається налаштована сума. Фактична знижка обмежується початковою ціною товару: кінцева ціна не може бути нижчою за нуль.

Якщо товар пов'язаний із кількома активними акціями зі знижками, обирається варіант із найменшою кінцевою ціною. Якщо кінцеві ціни однакові, перевага надається акції з меншим `SortOrder`, а потім — із назвою, що йде раніше без урахування регістру.

У відповіді товару акційна ціна повертається в `activePromotion`. Приклад:

```json
{
  "activePromotion": {
    "promotionId": "00000000-0000-0000-0000-000000000001",
    "title": "Осінній розпродаж",
    "slug": "autumn-sale",
    "discountType": "Percentage",
    "discountValue": 15,
    "originalPrice": 10000,
    "discountAmount": 1500,
    "discountedPrice": 8500
  }
}
```

Значення демонстраційні:

- `originalPrice` — початкова ціна товару;
- `discountValue` — налаштоване значення знижки;
- `discountAmount` — фактична сума знижки після округлення та обмеження початковою ціною;
- `discountedPrice` — кінцева ціна.

Якщо відповідної активної акції зі знижкою немає, `activePromotion` дорівнює `null`.

### Використання в кошику та замовленні

Розрахунок знижки не змінює базову ціну в `Product.Price`. Акційна ціна обчислюється під час формування відповіді товару.

Кошик також використовує найкращу доступну акційну ціну для `unitPrice` і `lineTotal`. Під час створення замовлення ціна акції розраховується повторно на момент оформлення, а кінцева ціна зберігається у знімку позиції замовлення (`OrderItem.UnitPrice` і `OrderItem.TotalPrice`). Тобто перевірка акційної ціни під час створення замовлення вже реалізована; це не лише майбутня задача каталогу.

## 8. Основні правила зберігання даних

- `Promotion.Slug` має унікальний індекс, тому однаковий slug не може належати двом записам.
- Для однієї акції не може бути двох перекладів з однаковим `CultureCode`.
- `PromotionProduct` використовує складений ключ `PromotionId` + `ProductId`, тому однаковий товар не може бути двічі прив'язаний до тієї самої акції.
- Видалення акції через API є м'якою деактивацією. Запис, переклади та зв'язки з товарами залишаються в базі.
- Фізичне видалення товару каскадно видаляє його зв'язки з акціями відповідно до конфігурації EF Core.

Публічний та адміністративний списки акцій наразі повертаються без пагінації.

## 9. Типові помилки API

| Код | Значення |
|---|---|
| `200 OK` | Запит виконано успішно |
| `201 Created` | Акцію створено |
| `400 Bad Request` | Некоректні дані, параметри, переклади або файл |
| `401 Unauthorized` | Відсутній або недійсний токен для адміністративного запиту |
| `403 Forbidden` | Користувач не має ролі `Admin` |
| `404 Not Found` | Акцію або файл не знайдено чи акція недоступна через публічний endpoint |
| `409 Conflict` | Конфлікт під час створення або оновлення, наприклад зайнятий slug |
| `500 Internal Server Error` | Непередбачена помилка сервера |

Помилки, які явно обробляються endpoints, повертаються в оболонці `RestResponse`. Автоматичні помилки валідації `[ApiController]` та відповіді механізму автентифікації й авторизації можуть мати стандартний формат ASP.NET Core, а не `RestResponse`.

Для `PUT` некоректне тіло запиту може бути відхилене до пошуку акції за ID. У такому разі API поверне `400 Bad Request`, навіть якщо переданий ID не існує.
