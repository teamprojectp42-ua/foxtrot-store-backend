# Categories API — документація категорій

Документ описує фактичні маршрути `CategoriesController` і відповідну поведінку `DataAccessor`: список і дерево категорій, отримання категорії, товари категорії, переклади, ієрархію, зображення, деактивацію та відновлення.

## Перед початком

`{{baseUrl}}` — базова адреса запущеного API, наприклад `https://localhost:7001`. Використовуйте фактичну адресу, яку показує застосунок.

Публічні GET-запити не вимагають токена. Для створення, редагування, деактивації, відновлення та завантаження зображення потрібен JWT користувача з роллю `Admin`:

```http
Authorization: Bearer {{adminToken}}
```

Підтримувані культури — `uk-UA` та `en-US`. Назва й опис повертаються для поточної культури запиту; якщо переклад відсутній, використовується український (`uk-UA`). Адміністративні відповіді містять колекцію `translations`; публічні GET-відповіді повертають `translations: []`.

## Короткий список endpoint-ів

| Метод | URL | Доступ | Призначення |
|---|---|---|---|
| `GET` | `/api/categories` | Публічний | Список активних категорій |
| `GET` | `/api/categories/tree` | Публічний | Дерево активних категорій |
| `GET` | `/api/categories/{id}` | Публічний | Отримати активну категорію за GUID |
| `GET` | `/api/categories/slug/{slug}` | Публічний | Отримати активну категорію за slug |
| `GET` | `/api/categories/{id}/products` | Публічний | Каталог активних товарів у категорії |
| `POST` | `/api/categories` | `Admin` | Створити категорію |
| `PUT` | `/api/categories/{id}` | `Admin` | Оновити slug, батьківську категорію, порядок і переклади |
| `DELETE` | `/api/categories/{id}` | `Admin` | Деактивувати категорію |
| `POST` | `/api/categories/{id}/restore` | `Admin` | Відновити категорію |
| `POST` | `/api/categories/{id}/image` | `Admin` | Завантажити або замінити зображення категорії |
| `GET` | `/api/categories/images/{imageKey}` | Публічний | Отримати файл зображення |

**Важливо:** усі GET-методи категорій, включно з адміністративними запитами, вибирають лише категорії з `IsActive == true`. Роль `Admin` додає переклади у відповідь, але не надає доступу до неактивних категорій через ці GET-маршрути.

## Формат відповідей

Більшість маршрутів повертають `RestResponse`:

```json
{
  "status": {
    "isOk": true,
    "code": 200,
    "message": "OK"
  },
  "meta": {
    "apiName": "Categories",
    "dataType": "json/array",
    "cacheTime": 0
  },
  "data": []
}
```

`meta` може містити `links`, `manipulations` та інші властивості `RestMeta`. Набір заповнених полів `meta` відрізняється залежно від endpoint-а. GET зображення повертає бінарний файл, а не JSON. Автоматична валідація `[ApiController]` може повернути `ProblemDetails`; не припускайте, що всі помилки мають однакове тіло.

## 1. Список категорій

```http
GET {{baseUrl}}/api/categories
```

Повертаються активні категорії, упорядковані за `sortOrder`, а потім за локалізованою назвою без урахування регістру. Пагінації та query-фільтрів немає.

Приклад публічної відповіді (значення ідентифікаторів наведено для ілюстрації):

```json
{
  "status": { "isOk": true, "code": 200, "message": "OK" },
  "meta": {
    "apiName": "Categories",
    "dataType": "json/array",
    "cacheTime": 0,
    "manipulations": ["GET"],
    "links": { "self": "/api/categories" }
  },
  "data": [
    {
      "id": "00000000-0000-0000-0000-000000000001",
      "name": "Смартфони",
      "slug": "smartfony",
      "description": "Смартфони та мобільні телефони",
      "imageUrl": "/api/categories/images/a1b2c3d4e5f678901234567890abcdef.webp",
      "parentCategoryId": null,
      "sortOrder": 0,
      "translations": []
    }
  ]
}
```

Для `Admin` об'єкт категорії також містить повний список перекладів, наприклад:

```json
"translations": [
  {
    "cultureCode": "uk-UA",
    "name": "Смартфони",
    "description": "Смартфони та мобільні телефони"
  },
  {
    "cultureCode": "en-US",
    "name": "Smartphones",
    "description": "Smartphones and mobile phones"
  }
]
```

`imageUrl` дорівнює `null`, якщо зображення не задане. Якщо в полі зберігається ключ локального файла, API формує відносний шлях `/api/categories/images/{imageKey}`. Абсолютний HTTP/HTTPS URL повертається без змін.

## 2. Дерево категорій

```http
GET {{baseUrl}}/api/categories/tree
```

Повертаються активні категорії з вкладеним масивом `children`. Кожен рівень сортується за `sortOrder`, а далі за локалізованою назвою без урахування регістру.

`CategoryTreeDto` містить `id`, `name`, `slug`, `imageUrl`, `sortOrder`, `translations` і `children`. Він не містить `description` або `parentCategoryId`: батьківсько-дочірні зв'язки представлені вкладеністю. Для публічного запиту `translations` порожній; для `Admin` містить доступні переклади.

Скорочений приклад:

```json
{
  "status": { "isOk": true, "code": 200, "message": "OK" },
  "meta": {
    "apiName": "CategoryTree",
    "dataType": "json/array",
    "cacheTime": 0,
    "manipulations": ["GET"],
    "links": { "self": "/api/categories/tree" }
  },
  "data": [
    {
      "id": "00000000-0000-0000-0000-000000000001",
      "name": "Електроніка",
      "slug": "elektronika",
      "imageUrl": null,
      "sortOrder": 0,
      "translations": [],
      "children": [
        {
          "id": "00000000-0000-0000-0000-000000000002",
          "name": "Смартфони",
          "slug": "smartfony",
          "imageUrl": null,
          "sortOrder": 0,
          "translations": [],
          "children": []
        }
      ]
    }
  ]
}
```

## 3. Отримати категорію за ID або slug

За GUID:

```http
GET {{baseUrl}}/api/categories/{{categoryId}}
```

За slug:

```http
GET {{baseUrl}}/api/categories/slug/smartfony
```

Обидва маршрути повертають лише активні категорії. `Admin` отримує додатково колекцію перекладів, але також не може через ці маршрути отримати неактивну категорію. Якщо категорію не знайдено або вона деактивована, повертається `404 Not Found`.

Для slug контролер перевіряє, що значення не порожнє й має не більше 150 символів. `DataAccessor` обрізає пробіли по краях і нормалізує slug до нижнього регістру.

## 4. Переклади категорії

Назва та опис зберігаються в `CategoryTranslation`, а не як поля запиту верхнього рівня. Створення потребує щонайменше одного перекладу й обов'язково перекладу `uk-UA`. Доступні культури: `uk-UA` і `en-US`.

Формат перекладу:

```json
{
  "cultureCode": "uk-UA",
  "name": "Смартфони",
  "description": "Смартфони та мобільні телефони"
}
```

| Поле | Правило |
|---|---|
| `cultureCode` | Обов'язковий; максимум 10 символів; бізнес-логіка приймає тільки `uk-UA` або `en-US` |
| `name` | Обов'язкове; після обрізання пробілів не може бути порожнім; максимум 150 символів |
| `description` | Необов'язкове, може бути `null`; максимум 1000 символів |

Один переклад на одну категорію й одну локаль забезпечується унікальним індексом `(CategoryId, CultureCode)`. Повторна локаль у запиті відхиляється. Якщо переклад для поточної мови відсутній, `Name` береться з `uk-UA`; `Description` може бути `null`, якщо він не заданий і в українському перекладі.

Під час оновлення передані переклади додаються або оновлюються за `CultureCode`. Локалі, яких немає у запиті, не видаляються. Тому `PUT` не є повною заміною колекції перекладів.

## 5. Товари категорії

```http
GET {{baseUrl}}/api/categories/{{categoryId}}/products?page=1&pageSize=12&sortBy=name&sortDirection=asc
```

Маршрут повертає каталог активних товарів, пов'язаних з активною категорією. Категорія береться з `categoryId` у маршруті: контролер перезаписує `query.CategoryId` цим значенням. Якщо категорія відсутня або неактивна, повертається `404 Not Found`.

Параметри відповідають `ProductCatalogQuery`:

| Параметр | Значення за замовчуванням | Правила |
|---|---|---|
| `page` | `1` | Не менше 1; розрахований offset не має перевищувати `Int32.MaxValue` |
| `pageSize` | `12` | Від 1 до 100 |
| `search` | немає | Пошук за SKU, назвою або описом; максимум 100 символів |
| `minPrice` | немає | Мінімальна ціна включно, не від'ємна |
| `maxPrice` | немає | Максимальна ціна включно, не від'ємна та не менша за `minPrice` |
| `brandId` | немає | GUID бренду; у каталозі враховується лише активний бренд |
| `inStock` | немає | `true` — запас більше нуля; `false` — запас нуль або менше |
| `sortBy` | `name` | `name`, `price` або `createdAt` |
| `sortDirection` | `asc` | `asc` або `desc` |

Пошук за текстом перевіряє SKU та переклади товару для поточної локалі й `uk-UA`. Для каталогу застосовуються спільні фільтри товарів, включно з активністю брендів і категорій. Відповідь містить масив товарів у `data`, пагінацію в `meta.pagination` і `categoryId`, `sortBy`, `sortDirection` у `meta.parameters`.

Приклад:

```http
GET {{baseUrl}}/api/categories/{{categoryId}}/products?page=2&pageSize=20&minPrice=100&maxPrice=1000&inStock=true&sortBy=price&sortDirection=desc
```

Некоректні параметри повертають `400 Bad Request`.

## 6. Створити категорію

Потрібна роль `Admin`.

```http
POST {{baseUrl}}/api/categories
Authorization: Bearer {{adminToken}}
Content-Type: application/json
```

Назва й опис передаються всередині `translations`, а не окремими полями верхнього рівня:

```json
{
  "slug": "smartfony",
  "parentCategoryId": null,
  "sortOrder": 0,
  "translations": [
    {
      "cultureCode": "uk-UA",
      "name": "Смартфони",
      "description": "Смартфони та мобільні телефони"
    },
    {
      "cultureCode": "en-US",
      "name": "Smartphones",
      "description": "Smartphones and mobile phones"
    }
  ]
}
```

| Поле | Правило |
|---|---|
| `slug` | Обов'язковий; 1–150 символів; латинські літери й цифри, розділені одиночними дефісами, без дефіса на початку/кінці |
| `parentCategoryId` | Необов'язковий; `null` означає кореневу категорію; заданий батько має існувати й бути активним |
| `sortOrder` | Ціле число від 0 до `Int32.MaxValue` |
| `translations` | Обов'язковий непорожній масив; переклад `uk-UA` обов'язковий під час створення |

`slug` переводиться в нижній регістр і має бути унікальним серед усіх категорій, зокрема деактивованих: slug деактивованої категорії не можна використати повторно. Зверніть увагу: `[RegularExpression]` перевіряє вхідний рядок до виконання `DataAccessor`, тому пробіли на початку/в кінці або інші символи поза шаблоном будуть відхилені ще на рівні валідації. Категорія не може бути власним предком; цикл в ієрархії відхиляється.

Зображення передається окремим запитом після створення категорії.

Успіх — `201 Created`; slug, що вже використовується, або конфлікт унікального індексу — `409 Conflict`; некоректні переклади, батьківська категорія або цикл — `400 Bad Request`.

## 7. Оновити категорію

Потрібна роль `Admin`.

```http
PUT {{baseUrl}}/api/categories/{{categoryId}}
Authorization: Bearer {{adminToken}}
Content-Type: application/json
```

```json
{
  "slug": "mobile-phones",
  "parentCategoryId": null,
  "sortOrder": 1,
  "translations": [
    {
      "cultureCode": "uk-UA",
      "name": "Мобільні телефони",
      "description": "Смартфони та мобільні телефони"
    }
  ]
}
```

`PUT` змінює `slug`, `parentCategoryId`, `sortOrder` і передані переклади. Він не приймає `isActive` чи `imageUrl`; ці дані змінюються окремими маршрутами.

Правила перекладів під час оновлення:

- `translations` має бути непорожнім масивом, але в поточному запиті не обов'язково передавати `uk-UA`, якщо цей переклад уже існує.
- Передані локалі додаються або оновлюються; не передані залишаються без змін.
- Категорію можна редагувати за ID, навіть якщо вона деактивована; `PUT` не активує її автоматично.
- Батьківська категорія, якщо задана, повинна бути активною. Не можна вказати саму категорію або її нащадка як батька.

Успіх — `200 OK`; категорію не знайдено — `404 Not Found`; некоректні дані/ієрархія — `400 Bad Request`; конфлікт slug — `409 Conflict`.

## 8. Деактивувати та відновити категорію

### Деактивація

```http
DELETE {{baseUrl}}/api/categories/{{categoryId}}
Authorization: Bearer {{adminToken}}
```

Це soft delete: запис лишається в БД, а `IsActive` змінюється на `false`. Категорію не можна деактивувати, доки в неї є активні дочірні категорії. Спочатку деактивуйте активних дітей. Успіх — `200 OK`; активну категорію не знайдено — `404 Not Found`; є активні дочірні категорії — `409 Conflict`.

Деактивація не видаляє зв'язки з товарами, дочірні категорії або зображення. Оскільки публічні запити каталогу фільтрують активні категорії, деактивована категорія недоступна через публічні GET-маршрути.

### Відновлення

```http
POST {{baseUrl}}/api/categories/{{categoryId}}/restore
Authorization: Bearer {{adminToken}}
```

Відновити можна лише деактивовану категорію. Якщо вона має батьківську категорію, батько повинен бути активним; інакше API повертає `409 Conflict`. Відновлення не активує автоматично дочірні категорії. Успіх — `200 OK`; відсутня або вже активна категорія — `404 Not Found`.

## 9. Завантажити або замінити зображення

Потрібна роль `Admin`. Endpoint приймає `multipart/form-data`:

```http
POST {{baseUrl}}/api/categories/{{categoryId}}/image
Authorization: Bearer {{adminToken}}
```

У Postman оберіть **Body → form-data**, додайте поле `file` типу **File** і виберіть зображення. Інші поля не потрібні. Не задавайте вручну boundary заголовка `multipart/form-data`.

Фактичні обмеження `LocalStorageService`:

- MIME-тип має бути `image/jpeg`, `image/png` або `image/webp`;
- вміст файла перевіряється декодером і має відповідати заявленому MIME-типу;
- максимальний розмір вхідного файла — 5 MiB (5 242 880 байтів);
- максимальний розмір зображення — 12 000 000 пікселів;
- порожні й анімовані зображення відхиляються;
- зображення декодується та перекодовується перед збереженням, що видаляє вихідні метадані та довільні кінцеві дані;
- ім'я файла генерується сервером; ключ має формат GUID без дефісів і розширення `.jpg`, `.png` або `.webp`.

Приклад успішної відповіді (`200 OK`):

```json
{
  "status": { "isOk": true, "code": 200, "message": "OK" },
  "meta": {
    "apiName": "CategoryImage",
    "dataType": "application/json",
    "manipulations": ["POST"],
    "links": {
      "parent": "/api/categories",
      "image": "/api/categories/images/a1b2c3d4e5f678901234567890abcdef.webp"
    }
  },
  "data": {
    "categoryId": "00000000-0000-0000-0000-000000000001",
    "imageKey": "a1b2c3d4e5f678901234567890abcdef.webp",
    "imageUrl": "/api/categories/images/a1b2c3d4e5f678901234567890abcdef.webp"
  }
}
```

Зображення можна завантажити лише для активної категорії. Якщо категорія не знайдена або неактивна, API намагається видалити новий файл і повертає `404 Not Found`. Якщо перевірка файла завершується `InvalidDataException`, повертається `400 Bad Request`.

Під час заміни спочатку зберігається новий файл і оновлюється запис категорії, після чого сервер намагається видалити попередній файл, якщо його ключ має формат локального ключа сховища. Помилка очищення старого файла записується в лог і не скасовує успішну заміну. Якщо збереження в БД не вдається, сервер намагається прибрати новий файл і повторно викидає помилку.

## 10. Отримати файл зображення

```http
GET {{baseUrl}}/api/categories/images/{{imageKey}}
```

Endpoint публічний і повертає бінарний файл. `Content-Type` визначається за розширенням: `.jpg` — `image/jpeg`, `.png` — `image/png`, `.webp` — `image/webp`.

`LocalStorageService` додатково перевіряє, що ключ не є абсолютним шляхом і не містить `/` або `\`, має дозволене розширення та ім'я у форматі GUID без дефісів. Непідтримуване розширення або некоректний ключ повертає `400 Bad Request`; файл відсутній — `404 Not Found`.

Запит читає файл за ключем і не перевіряє, чи наразі існує активна категорія, яка на нього посилається. Тому доступність відомого файла залежить від наявності самого файла у сховищі, а не від активності категорії.

## 11. HTTP-статуси

| Код | Значення |
|---|---|
| `200 OK` | Успішне читання, оновлення, деактивація, відновлення або завантаження зображення |
| `201 Created` | Категорію створено |
| `400 Bad Request` | Некоректний slug, переклади, ієрархія, параметри каталогу або зображення |
| `401 Unauthorized` | Для адміністративної операції відсутній або недійсний JWT |
| `403 Forbidden` | JWT валідний, але користувач не має ролі `Admin` |
| `404 Not Found` | Категорія не знайдена/неактивна для відповідного запиту або файл відсутній |
| `409 Conflict` | Slug уже зайнятий, є активні дочірні категорії або неактивний батько блокує відновлення |

Форма відповіді залежить від маршруту: більшість повертає `RestResponse`, а GET зображення — файл. Контролер не перетворює всі неочікувані помилки файлової системи або БД на окремі контрольовані відповіді; їхній HTTP-відгук залежить від конфігурації обробки помилок у застосунку.

## 12. Перевірка через Postman

1. Увійдіть під користувачем `Admin` і скопіюйте `accessToken`.
2. Виконайте `GET /api/categories` і `GET /api/categories/tree` без токена, а потім із токеном Admin: перевірте, що Admin отримує `translations`.
3. Створіть категорію через `POST /api/categories`, передавши `slug`, `parentCategoryId`, `sortOrder` і `translations`.
4. Перевірте `GET /api/categories/{id}` та `GET /api/categories/slug/{slug}` для `uk-UA` та `en-US`.
5. Перевірте `GET /api/categories/{id}/products` з пагінацією, фільтрами й сортуванням.
6. Завантажте зображення через `POST /api/categories/{id}/image`, а потім відкрийте `imageUrl`.
7. Створіть дочірню категорію й перевірте, що батьківську не можна деактивувати, доки дитина активна.
8. Деактивуйте дочірню категорію, потім батьківську; перевірте публічні GET-запити.
9. Перевірте, що відновлення дочірньої категорії відхиляється, поки її батько неактивний.
10. Повторіть адміністративні `POST`, `PUT`, `DELETE` і завантаження зображення з токеном `User`: очікується `403 Forbidden`.
