# Categories API — інструкція з використання

Цей документ пояснює, як працювати з категоріями через API Foxtrot Store Backend: переглядати список і дерево категорій, отримувати категорію за ID або `slug`, переглядати товари категорії, а також створювати, редагувати, деактивувати, відновлювати категорії та керувати їхніми зображеннями.

## Перед початком

У прикладах `{{baseUrl}}` означає адресу запущеного API, наприклад `https://localhost:7001`. Порт наведено лише як приклад — використовуйте адресу, яку показує ваш застосунок під час запуску.

Для адміністративних операцій потрібен JWT-токен користувача з роллю `Admin`. Отримайте його через наявний у проєкті API авторизації.

У Postman для захищених запитів передавайте заголовок:

```http
Authorization: Bearer {{adminToken}}
```

## Короткий список запитів

| Метод | URL | Для чого |
|---|---|---|
| `GET` | `/api/categories` | Отримати список активних категорій |
| `GET` | `/api/categories/tree` | Отримати дерево активних категорій |
| `GET` | `/api/categories/{id}` | Отримати категорію за ID |
| `GET` | `/api/categories/slug/{slug}` | Отримати категорію за `slug` |
| `GET` | `/api/categories/{id}/products` | Переглянути товари категорії з фільтрами та пагінацією |
| `POST` | `/api/categories` | Створити категорію — потрібен `Admin` |
| `PUT` | `/api/categories/{id}` | Оновити категорію — потрібен `Admin` |
| `DELETE` | `/api/categories/{id}` | Деактивувати категорію — потрібен `Admin` |
| `POST` | `/api/categories/{id}/restore` | Відновити категорію — потрібен `Admin` |
| `GET` | `/api/categories/images/{imageKey}` | Отримати файл зображення категорії |
| `POST` | `/api/categories/{id}/image` | Завантажити або замінити зображення — потрібен `Admin` |

## 1. Перегляд категорій

### Список категорій

```http
GET {{baseUrl}}/api/categories
```

Запит повертає всі активні категорії, відсортовані за `sortOrder`, а потім за назвою. Пагінації та query-фільтрів для цього endpoint немає.

Приклад відповіді (значення наведено для ілюстрації):

```json
{
  "status": {
    "isOk": true,
    "code": 200,
    "message": "OK"
  },
  "meta": {
    "apiName": "Categories",
    "dataType": "json/array",
    "cacheTime": 0,
    "manipulations": ["GET"],
    "links": {
      "self": "/api/categories"
    }
  },
  "data": [
    {
      "id": "00000000-0000-0000-0000-000000000001",
      "name": "Смартфони",
      "slug": "smartfony",
      "description": "Смартфони та мобільні телефони",
      "imageUrl": "/api/categories/images/a1b2c3d4e5f678901234567890abcdef.webp",
      "parentCategoryId": null,
      "sortOrder": 0
    }
  ]
}
```

`parentCategoryId` містить ID батьківської категорії або `null`, якщо категорія є кореневою. `imageUrl` містить шлях до зображення, якщо воно завантажене; інакше значення буде `null`.

### Дерево категорій

```http
GET {{baseUrl}}/api/categories/tree
```

Endpoint повертає активні категорії у вигляді дерева. Дочірні категорії містяться в масиві `children`. Сортування всередині кожного рівня виконується за `sortOrder`, а при однаковому значенні — за назвою.

Приклад відповіді:

```json
{
  "status": {
    "isOk": true,
    "code": 200,
    "message": "OK"
  },
  "meta": {
    "apiName": "CategoryTree",
    "dataType": "json/array",
    "cacheTime": 0,
    "manipulations": ["GET"],
    "links": {
      "self": "/api/categories/tree"
    }
  },
  "data": [
    {
      "id": "00000000-0000-0000-0000-000000000001",
      "name": "Електроніка",
      "slug": "elektronika",
      "imageUrl": null,
      "sortOrder": 0,
      "children": [
        {
          "id": "00000000-0000-0000-0000-000000000002",
          "name": "Смартфони",
          "slug": "smartfony",
          "imageUrl": null,
          "sortOrder": 0,
          "children": []
        }
      ]
    }
  ]
}
```

У `CategoryTreeDto` немає опису та `parentCategoryId`: зв'язок між рівнями представлено вкладеним масивом `children`.

## 2. Отримати одну категорію

### За ID

```http
GET {{baseUrl}}/api/categories/{{categoryId}}
```

`categoryId` — GUID категорії, який повертає API.

### За slug

```http
GET {{baseUrl}}/api/categories/slug/smartfony
```

`slug` — адресне ім'я категорії. Під час створення й оновлення воно нормалізується до нижнього регістру.

Успішні відповіді містять об'єкт категорії в полі `data`. Публічні запити повертають лише активні категорії. Для неіснуючої або деактивованої категорії повертається `404 Not Found`. Для порожнього `slug` або рядка довшого за 150 символів endpoint повертає `400 Bad Request`.

## 3. Отримати товари категорії

```http
GET {{baseUrl}}/api/categories/{{categoryId}}/products
```

Endpoint повертає активні товари, пов'язані з указаною активною категорією. Додаткові параметри працюють за принципом каталогу товарів, але `categoryId` завжди береться з маршруту: передане в query значення не змінює категорію поточного запиту.

### Параметри каталогу

| Параметр | Приклад | Опис |
|---|---|---|
| `page` | `page=2` | Номер сторінки, починаючи з 1 |
| `pageSize` | `pageSize=20` | Кількість товарів на сторінці: від 1 до 100 |
| `search` | `search=phone` | Пошук за назвою, SKU або описом, максимум 100 символів |
| `minPrice` | `minPrice=100` | Мінімальна ціна включно |
| `maxPrice` | `maxPrice=1000` | Максимальна ціна включно |
| `brandId` | `brandId=<GUID>` | Фільтр за ID бренду |
| `inStock` | `inStock=true` | `true` — є залишок; `false` — залишку немає |
| `sortBy` | `sortBy=price` | Поле сортування: `name`, `price` або `createdAt` |
| `sortDirection` | `sortDirection=desc` | Напрямок сортування: `asc` або `desc` |

Приклад: отримати другу сторінку товарів цієї категорії, які коштують від 100 до 1000, є в наявності та відсортовані від дорожчих до дешевших:

```http
GET {{baseUrl}}/api/categories/{{categoryId}}/products?page=2&pageSize=20&minPrice=100&maxPrice=1000&inStock=true&sortBy=price&sortDirection=desc
```

Успішна відповідь містить товари в `data`, а інформацію про сторінки — у `meta.pagination`. У `meta.parameters` повертаються `categoryId`, `sortBy` і `sortDirection`.

Некоректні параметри, наприклад `page=0`, `pageSize=200`, від'ємна ціна, `minPrice` більша за `maxPrice`, пошук довший за 100 символів або невідоме поле сортування, повертають `400 Bad Request`. Якщо категорія не існує або деактивована, повертається `404 Not Found`.

## 4. Створити категорію

Потрібен токен адміністратора.

```http
POST {{baseUrl}}/api/categories
Authorization: Bearer {{adminToken}}
Content-Type: application/json
```

Тіло запиту:

```json
{
  "name": "Смартфони",
  "slug": "smartfony",
  "description": "Смартфони та мобільні телефони",
  "parentCategoryId": null,
  "sortOrder": 0
}
```

Основні правила для полів:

- `name` — обов'язкова назва, від 1 до 150 символів;
- `slug` — обов'язкове значення від 1 до 150 символів; дозволені латинські літери й цифри, розділені дефісами, наприклад `smartfony` або `mobile-phones`;
- `description` — необов'язковий опис до 1000 символів;
- `parentCategoryId` — `null` для кореневої категорії або ID активної батьківської категорії;
- `sortOrder` — ціле число не менше нуля.

Категорія не може бути власним предком. Батьківська категорія повинна існувати й бути активною. `slug` зберігається в нижньому регістрі та має бути унікальним серед усіх категорій, зокрема деактивованих. Тому `slug` деактивованої категорії не можна повторно використати для нової категорії.

Зображення не передається в JSON. Спочатку створіть категорію, скопіюйте її `id` з відповіді, а потім завантажте зображення окремим запитом (див. розділ 8).

Успішне створення повертає `201 Created`. Уже використаний `slug` повертає `409 Conflict`; некоректна або неактивна батьківська категорія — `400 Bad Request`.

## 5. Оновити категорію

Потрібен токен адміністратора. Запит `PUT` надсилає набір основних полів категорії після оновлення.

```http
PUT {{baseUrl}}/api/categories/{{categoryId}}
Authorization: Bearer {{adminToken}}
Content-Type: application/json
```

Приклад тіла:

```json
{
  "name": "Мобільні телефони",
  "slug": "mobile-phones",
  "description": "Смартфони та мобільні телефони",
  "parentCategoryId": null,
  "sortOrder": 1
}
```

Правила полів відповідають створенню категорії. `parentCategoryId` можна змінювати на ID іншої активної категорії або на `null`. Не можна вказати саму категорію чи її нащадка як батьківську категорію, оскільки це створило б цикл.

Запит не приймає `isActive` або `imageUrl`: стан активності змінюється окремими запитами, а зображення завантажується через endpoint для файлу. За поточною реалізацією адміністратор може редагувати категорію за наявним ID, навіть якщо вона деактивована; сам запит `PUT` не активує її.

Очікувані відповіді: `200 OK` — оновлено; `400 Bad Request` — некоректні дані або батьківська категорія; `404 Not Found` — категорії з таким ID немає; `409 Conflict` — `slug` уже використовується.

## 6. Деактивувати та відновити категорію

Категорії деактивуються м'яко: запис залишається в базі, а публічні endpoints перестають його повертати.

### Деактивація

```http
DELETE {{baseUrl}}/api/categories/{{categoryId}}
Authorization: Bearer {{adminToken}}
```

Успішна відповідь — `200 OK`. Якщо категорія вже неактивна або не існує, повертається `404 Not Found`.

Категорію з активними дочірніми категоріями деактивувати не можна. Спочатку деактивуйте її активні дочірні категорії. У такому разі endpoint повертає `409 Conflict` з повідомленням про необхідність деактивації дочірніх категорій.

### Відновлення

```http
POST {{baseUrl}}/api/categories/{{categoryId}}/restore
Authorization: Bearer {{adminToken}}
```

Успішна відповідь — `200 OK`. Якщо категорія відсутня або вже активна, повертається `404 Not Found`.

Якщо категорія має батьківську категорію, батьківська категорія повинна бути активною. Інакше повертається `409 Conflict`. Відновлення категорії не відновлює автоматично її деактивованих дочірніх категорій.

## 7. Завантажити зображення категорії

Потрібен токен адміністратора. Файл передається через `multipart/form-data`.

```http
POST {{baseUrl}}/api/categories/{{categoryId}}/image
Authorization: Bearer {{adminToken}}
```

У Postman:

1. Виберіть метод `POST` і URL вище, замінивши `{{categoryId}}` на ID активної категорії.
2. Відкрийте **Body → form-data**.
3. Додайте поле `file`, змініть його тип на **File** і виберіть зображення.
4. Додайте заголовок авторизації та надішліть запит.

Дозволені формати — JPEG, PNG і WEBP. Максимальний розмір файлу — 5 MiB, максимальний розмір зображення — 12 000 000 пікселів. Порожні файли та анімовані зображення не підтримуються. Сервер перевіряє заявлений MIME-тип і фактичний формат зображення, а перед збереженням нормалізує його.

Приклад успішної відповіді:

```json
{
  "status": {
    "isOk": true,
    "code": 200,
    "message": "OK"
  },
  "meta": {
    "apiName": "CategoryImage",
    "dataType": "application/json",
    "manipulations": ["POST"],
    "links": {
      "parent": "/api/categories",
      "image": "/api/categories/images/a1b2c3d4e5f678901234567890abcdef.webp"
    }
  },
  "data": {
    "categoryId": "00000000-0000-0000-0000-000000000001",
    "imageKey": "a1b2c3d4e5f678901234567890abcdef.webp",
    "imageUrl": "/api/categories/images/a1b2c3d4e5f678901234567890abcdef.webp"
  }
}
```

Збережіть `imageKey` або знову отримайте категорію через `GET /api/categories/{id}` — у полі `imageUrl` має бути шлях до зображення. Повторне завантаження замінює поточне зображення категорії; після успішного оновлення сервер намагається видалити попередній файл.

Якщо файл не переданий, порожній або не пройшов перевірку, endpoint повертає `400 Bad Request`. Якщо категорію не знайдено або вона неактивна, повертається `404 Not Found`.

## 8. Отримати зображення категорії

```http
GET {{baseUrl}}/api/categories/images/{{imageKey}}
```

Цей endpoint публічний і не потребує токена. `imageKey` — ключ, який повернув endpoint завантаження, наприклад `a1b2c3d4e5f678901234567890abcdef.webp`.

Успішний запит повертає байти файлу з відповідним MIME-типом, а не JSON. У браузері можна відкрити повну адресу зображення; у Postman — переглянути або зберегти відповідь як файл.

Дозволені розширення: `.jpg`, `.png`, `.webp`. Непідтримуване розширення повертає `400 Bad Request`; некоректний ключ — `400 Bad Request`; якщо файла немає — `404 Not Found`.

Шлях `imageUrl` у відповідях категорії є відносним шляхом до API, наприклад:

```text
/api/categories/images/a1b2c3d4e5f678901234567890abcdef.webp
```

Якщо frontend працює на іншому домені або порту, додайте перед цим шляхом базову адресу API.
