# Cart API — інструкція з використання

Цей документ описує роботу з кошиком Foxtrot Store Backend: отримання кошика, додавання товарів, зміну кількості, видалення позицій та очищення кошика.

## Перед початком

У прикладах `{{baseUrl}}` — базова адреса запущеного API, наприклад `https://localhost:7001`. Використовуйте адресу, яку показує застосунок під час запуску.

Усі endpoint-и кошика доступні лише авторизованому користувачу з роллю `User`. Для кожного запиту передавайте JWT access token:

```http
Authorization: Bearer {{userToken}}
```

Кошик визначається сервером за ID користувача з JWT (`sub` або `NameIdentifier`). Передавати `userId` у тілі чи URL запиту не потрібно.

`Manager` та `Admin` не мають доступу до endpoint-ів кошика, оскільки контролер обмежений атрибутом `[Authorize(Roles = AppRoles.User)]`.

## Короткий список endpoint-ів

| Метод | URL | Призначення | Доступ |
|---|---|---|---|
| `GET` | `/api/cart` | Отримати поточний кошик | `User` |
| `POST` | `/api/cart/items` | Додати товар або збільшити його кількість | `User` |
| `PUT` | `/api/cart/items/{productId}` | Встановити кількість товару | `User` |
| `DELETE` | `/api/cart/items/{productId}` | Видалити товар із кошика | `User` |
| `DELETE` | `/api/cart` | Очистити кошик | `User` |

## Формат відповіді

Успішні відповіді використовують оболонку `RestResponse`:

```json
{
  "status": {
    "isOk": true,
    "code": 200,
    "message": "OK"
  },
  "meta": {
    "apiName": "Cart",
    "dataType": "application/json",
    "cacheTime": 0,
    "manipulations": ["GET"],
    "links": {
      "self": "/api/cart"
    }
  },
  "data": {
    "items": [],
    "totalAvailableQuantity": 0,
    "totalAmount": 0
  }
}
```

Приклад показує порожній кошик. Значення `serverTime` та решта властивостей `meta` формуються моделлю `RestMeta`.

## 1. Отримати кошик

```http
GET {{baseUrl}}/api/cart
Authorization: Bearer {{userToken}}
```

Успішна відповідь — `200 OK`. Якщо кошик ще не створений або не містить позицій, API повертає порожній `CartResponseDto`.

Приклад `data` для кошика з товаром:

```json
{
  "items": [
    {
      "id": "00000000-0000-0000-0000-000000000010",
      "productId": "00000000-0000-0000-0000-000000000001",
      "sku": "PHONE-001",
      "productName": "Приклад смартфона",
      "originalUnitPrice": 10000.00,
      "unitPrice": 9000.00,
      "activePromotion": {
        "promotionId": "00000000-0000-0000-0000-000000000100",
        "title": "Знижка на смартфон",
        "slug": "znizhka-na-smartfon",
        "discountType": "Percentage",
        "discountValue": 10.00,
        "originalPrice": 10000.00,
        "discountAmount": 1000.00,
        "discountedPrice": 9000.00
      },
      "requestedQuantity": 5,
      "availableQuantity": 3,
      "stockQuantity": 3,
      "isProductActive": true,
      "isAvailable": true,
      "isQuantityAdjusted": true,
      "availabilityStatus": "InsufficientStock",
      "lineTotal": 27000.00
    }
  ],
  "totalAvailableQuantity": 3,
  "totalAmount": 27000.00
}
```

Це ілюстративний приклад. `activePromotion` може бути `null`, якщо для товару немає чинної акції зі знижкою.

### Як працюють кількості та залишки

У базі `CartItem.Quantity` зберігає кількість, яку запросив покупець. Під час читання кошика API окремо обчислює доступну кількість:

- `requestedQuantity` — кількість, яку покупець додав у кошик;
- `availableQuantity` — кількість, яку зараз можна придбати: мінімум із запитаної кількості та поточного залишку; для неактивного товару — `0`;
- `stockQuantity` — поточний складський залишок;
- `isQuantityAdjusted` — чи відрізняється доступна кількість від запитаної;
- `lineTotal` — актуальна ціна одиниці, помножена на `availableQuantity`.

Можливі значення `availabilityStatus`:

| Значення | Значення для користувача |
|---|---|
| `Available` | Товар активний, запитана кількість доступна |
| `InsufficientStock` | На складі залишилося менше, ніж запитано |
| `OutOfStock` | Залишок дорівнює нулю |
| `Inactive` | Товар деактивований |

Наприклад, якщо в кошику запитано 5 одиниць, а на складі залишилося 3, у базі залишиться `Quantity = 5`, а відповідь покаже `requestedQuantity = 5` та `availableQuantity = 3`. Збільшення залишку пізніше автоматично збільшить доступну кількість під час наступного отримання кошика.

`totalAmount` обчислюється сервером як сума `lineTotal` усіх позицій. Для недоступного або деактивованого товару доступна кількість і сума позиції дорівнюють нулю.

Ціни не зберігаються в `CartItem`: API щоразу використовує актуальну ціну товару та чинні акції. Якщо одночасно діє декілька акцій, використовується найвигідніша ціна за наявним алгоритмом backend.

## 2. Додати товар

```http
POST {{baseUrl}}/api/cart/items
Authorization: Bearer {{userToken}}
Content-Type: application/json
```

Тіло запиту:

```json
{
  "productId": "00000000-0000-0000-0000-000000000001",
  "quantity": 2
}
```

`productId` — GUID товару. `quantity` має бути цілим числом від 1 і більше; значення за замовчуванням у DTO — `1`.

Якщо товар уже є в кошику, кількість збільшується, а нова позиція не створюється. Сумарна запитана кількість не може перевищувати поточний залишок під час додавання.

Успішна відповідь — `200 OK` з оновленим `CartResponseDto`.

Типові помилки:

- `400 Bad Request` — невалідне тіло, порожній `productId` або кількість менша за 1;
- `401 Unauthorized` — токен відсутній, недійсний або прострочений;
- `403 Forbidden` — користувач не має ролі `User`;
- `404 Not Found` — товар не знайдений;
- `409 Conflict` — товар неактивний, відсутній на складі або запитана кількість перевищує залишок.

## 3. Змінити кількість товару

```http
PUT {{baseUrl}}/api/cart/items/{{productId}}
Authorization: Bearer {{userToken}}
Content-Type: application/json
```

Тіло запиту:

```json
{
  "quantity": 3
}
```

`quantity` має бути цілим числом від 1 і більше. Значення встановлює нову запитану кількість, а не додається до попередньої.

Успішна відповідь — `200 OK` з оновленим кошиком.

Типові помилки:

- `400 Bad Request` — кількість менша за 1;
- `404 Not Found` — кошик або позиція з таким `productId` не знайдені;
- `409 Conflict` — товар неактивний, відсутній на складі або нова кількість перевищує залишок;
- `401 Unauthorized` / `403 Forbidden` — проблема з токеном або роллю.

## 4. Видалити товар із кошика

```http
DELETE {{baseUrl}}/api/cart/items/{{productId}}
Authorization: Bearer {{userToken}}
```

Успішна відповідь — `200 OK` з оновленим `CartResponseDto`.

Якщо кошик або позицію не знайдено, повертається `404 Not Found`.

## 5. Очистити кошик

```http
DELETE {{baseUrl}}/api/cart
Authorization: Bearer {{userToken}}
```

Успішна відповідь — `200 OK` з порожнім `CartResponseDto`:

```json
{
  "items": [],
  "totalAvailableQuantity": 0,
  "totalAmount": 0
}
```

Якщо кошика ще немає, endpoint також повертає успішну відповідь із порожнім результатом.

## 6. Правила та обмеження

- Один авторизований користувач має одну корзину.
- Один товар може бути представлений у кошику лише однією позицією.
- Повторне додавання товару збільшує кількість існуючої позиції.
- Кількість у базі не змінюється автоматично лише через зменшення складського залишку; фактична доступність перераховується під час читання.
- При додаванні або явній зміні кількості backend перевіряє активність товару та залишок.
- Ціни, знижки та загальна сума розраховуються на backend.
- Оформлення замовлення повторно перевіряє залишки та ціни; правила описані в `OrdersApi.md`.
- Зміни кошика виконуються з транзакціями та блокуванням рядків кошика/товару для захисту від одночасних змін.

## 7. Перевірка через Postman

1. Увійдіть під користувачем із роллю `User` та скопіюйте `data.accessToken`.
2. Виконайте `GET /api/cart` — для нового користувача очікується порожній кошик.
3. Виконайте `POST /api/cart/items` із дійсним ID активного товару.
4. Повторіть `POST` для того самого товару й перевірте збільшення кількості в одній позиції.
5. Виконайте `PUT /api/cart/items/{productId}` та перевірте встановлення нового значення кількості.
6. Перевірте `DELETE /api/cart/items/{productId}` і `DELETE /api/cart`.
7. Перевірте випадки неіснуючого, неактивного товару та недостатнього залишку.
8. Спробуйте викликати endpoint кошика без токена та з ролями `Manager` і `Admin`; очікується відмова в доступі.
