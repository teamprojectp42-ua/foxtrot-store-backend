# Brands API — інструкція з використання

Цей документ пояснює, як працювати з брендами через API Foxtrot Store Backend: переглядати список брендів, отримувати бренд за ID або `slug`, переглядати товари бренду, створювати й редагувати бренди, деактивувати та відновлювати їх, а також завантажувати й відкривати логотипи.

## Перед початком

У прикладах `{{baseUrl}}` означає адресу запущеного API, наприклад `https://localhost:7001`. Порт наведено лише як приклад — використовуйте адресу, яку показує застосунок під час запуску.

Для адміністративних операцій потрібен JWT-токен користувача з роллю `Admin`. Отримайте його через наявний у проєкті API авторизації.

У Postman для захищених запитів передавайте заголовок:

```http
Authorization: Bearer {{adminToken}}
```

Логотип завантажується окремим запитом через `multipart/form-data`. Його не потрібно передавати в JSON під час створення або редагування бренду.

## Короткий список запитів

| Метод | URL | Для чого |
|---|---|---|
| `GET` | `/api/brands` | Отримати список активних брендів |
| `GET` | `/api/brands/{id}` | Отримати бренд за ID |
| `GET` | `/api/brands/slug/{slug}` | Отримати бренд за `slug` |
| `GET` | `/api/brands/{id}/products` | Переглянути товари бренду з фільтрами та пагінацією |
| `POST` | `/api/brands` | Створити бренд — потрібен `Admin` |
| `PUT` | `/api/brands/{id}` | Оновити дані бренду — потрібен `Admin` |
| `DELETE` | `/api/brands/{id}` | Деактивувати бренд — потрібен `Admin` |
| `POST` | `/api/brands/{id}/restore` | Відновити бренд — потрібен `Admin` |
| `GET` | `/api/brands/images/{imageKey}` | Отримати файл логотипа |
| `POST` | `/api/brands/{id}/logo` | Завантажити або замінити логотип — потрібен `Admin` |

## 1. Перегляд брендів

### Список брендів

```http
GET {{baseUrl}}/api/brands
```

Запит повертає всі активні бренди, відсортовані за назвою. Пагінації та query-фільтрів для цього endpoint немає. Деактивовані бренди до публічного списку не потрапляють.

Приклад відповіді (значення наведено для ілюстрації):

```json
{
  "status": {
    "isOk": true,
    "code": 200,
    "message": "OK"
  },
  "meta": {
    "apiName": "Brands",
    "dataType": "json/array",
    "cacheTime": 0,
    "manipulations": ["GET"],
    "links": {
      "self": "/api/brands"
    }
  },
  "data": [
    {
      "id": "00000000-0000-0000-0000-000000000001",
      "name": "Samsung",
      "slug": "samsung",
      "description": "Електроніка та побутова техніка",
      "logoUrl": "/api/brands/images/a1b2c3d4e5f678901234567890abcdef.webp"
    }
  ]
}
```

`logoUrl` містить шлях до зображення, якщо логотип збережений у LocalStorage. Якщо логотип не заданий, значення буде `null`. Для старих записів, у яких збережено зовнішню URL-адресу, метод формування посилання залишає її без змін.

### Отримати бренд за ID

```http
GET {{baseUrl}}/api/brands/{{brandId}}
```

`brandId` — GUID бренду, який повертає API. Успішна відповідь містить об'єкт бренду в полі `data`. Якщо бренд не існує або деактивований, повертається `404 Not Found`.

### Отримати бренд за slug

```http
GET {{baseUrl}}/api/brands/slug/samsung
```

`slug` — адресне ім'я бренду. Під час створення та оновлення воно обрізається по краях і зберігається в нижньому регістрі. Для порожнього `slug` або рядка довшого за 150 символів endpoint повертає `400 Bad Request`. Якщо активного бренду з таким `slug` немає, повертається `404 Not Found`.

## 2. Отримати товари бренду

```http
GET {{baseUrl}}/api/brands/{{brandId}}/products
```

Endpoint повертає активні товари вказаного активного бренду. `brandId` береться з маршруту, тому query-параметр `brandId` не може змінити бренд, за яким виконується запит. Інші параметри каталогу можна комбінувати з маршрутом бренду.

### Параметри каталогу

| Параметр | Приклад | Опис |
|---|---|---|
| `page` | `page=2` | Номер сторінки, починаючи з 1 |
| `pageSize` | `pageSize=20` | Кількість товарів на сторінці: від 1 до 100 |
| `search` | `search=phone` | Пошук за назвою, SKU або описом, максимум 100 символів |
| `minPrice` | `minPrice=100` | Мінімальна ціна включно; не може бути від'ємною |
| `maxPrice` | `maxPrice=1000` | Максимальна ціна включно; не може бути від'ємною |
| `categoryId` | `categoryId=<GUID>` | Додатковий фільтр за категорією |
| `inStock` | `inStock=true` | `true` — є залишок; `false` — залишку немає |
| `sortBy` | `sortBy=price` | Поле сортування: `name`, `price` або `createdAt` |
| `sortDirection` | `sortDirection=desc` | Напрямок сортування: `asc` або `desc` |

Приклад: отримати другу сторінку товарів бренду з ціною від 100 до 1000, які є в наявності, і показати спочатку дорожчі:

```http
GET {{baseUrl}}/api/brands/{{brandId}}/products?page=2&pageSize=20&minPrice=100&maxPrice=1000&inStock=true&sortBy=price&sortDirection=desc
```

Успішна відповідь містить товари в `data`, інформацію про сторінки — у `meta.pagination`, а `brandId`, `sortBy` і `sortDirection` — у `meta.parameters`.

Приклад структури відповіді:

```json
{
  "status": {
    "isOk": true,
    "code": 200,
    "message": "OK"
  },
  "meta": {
    "apiName": "BrandProducts",
    "dataType": "json/array",
    "cacheTime": 0,
    "manipulations": ["GET"],
    "links": {
      "self": "/api/brands/00000000-0000-0000-0000-000000000001/products"
    },
    "pagination": {
      "page": 1,
      "pageSize": 12,
      "totalPages": 2,
      "totalItems": 15
    },
    "parameters": {
      "brandId": "00000000-0000-0000-0000-000000000001",
      "sortBy": "name",
      "sortDirection": "asc"
    }
  },
  "data": []
}
```

Числа та ID в прикладі демонстраційні; `data` міститиме масив товарів, що відповідають запиту.

Некоректні параметри, наприклад `page=0`, `pageSize=200`, надто велика сторінка, від'ємна ціна, `minPrice` більша за `maxPrice`, пошук довший за 100 символів або невідоме поле сортування, повертають `400 Bad Request`. Якщо бренд не існує або деактивований, повертається `404 Not Found`.

## 3. Створити бренд

Потрібен токен адміністратора.

```http
POST {{baseUrl}}/api/brands
Authorization: Bearer {{adminToken}}
Content-Type: application/json
```

Тіло запиту:

```json
{
  "name": "Samsung",
  "slug": "samsung",
  "description": "Електроніка та побутова техніка"
}
```

Правила для полів:

- `name` — обов'язкова назва, від 1 до 150 символів;
- `slug` — обов'язкове значення від 1 до 150 символів; дозволені латинські літери та цифри, розділені одиночними дефісами, наприклад `samsung` або `samsung-mobile`;
- `description` — необов'язковий опис до 1000 символів.

`slug` унікальний серед усіх брендів, включно з деактивованими. Тому `slug` деактивованого бренду не можна використати для іншого бренду, доки старий запис залишається в базі.

Логотип не передається в JSON. Спочатку створіть бренд, скопіюйте `id` з відповіді, а потім завантажте логотип через `POST /api/brands/{id}/logo`.

Успішне створення повертає `201 Created`. Якщо `slug` уже використовується, повертається `409 Conflict`. Помилки перевірки DTO зазвичай повертають `400 Bad Request`.

Приклад успішної відповіді:

```json
{
  "status": {
    "isOk": true,
    "code": 201,
    "message": "Created"
  },
  "meta": {
    "apiName": "Brand",
    "dataType": "json/object",
    "manipulations": ["GET"],
    "links": {
      "parent": "/api/brands",
      "self": "/api/brands/00000000-0000-0000-0000-000000000001"
    }
  },
  "data": {
    "id": "00000000-0000-0000-0000-000000000001",
    "name": "Samsung",
    "slug": "samsung",
    "description": "Електроніка та побутова техніка",
    "logoUrl": null
  }
}
```

## 4. Оновити бренд

Потрібен токен адміністратора. Запит `PUT` оновлює основні поля бренду, але не його логотип і не стан активності.

```http
PUT {{baseUrl}}/api/brands/{{brandId}}
Authorization: Bearer {{adminToken}}
Content-Type: application/json
```

Приклад тіла:

```json
{
  "name": "Samsung Electronics",
  "slug": "samsung-electronics",
  "description": "Оновлений опис бренду"
}
```

Правила полів такі самі, як під час створення. Властивості `logoUrl` та `isActive` не входять до `BrandUpdateRequest`: логотип змінюється окремим endpoint, а деактивація й відновлення виконуються окремими запитами.

Адміністратор може редагувати бренд за наявним ID, навіть якщо він деактивований. Оновлення не активує його повторно.

Очікувані відповіді: `200 OK` — дані оновлено; `400 Bad Request` — помилка валідації DTO; `404 Not Found` — бренду з таким ID немає; `409 Conflict` — `slug` уже використовується іншим брендом.

## 5. Деактивувати та відновити бренд

Бренди деактивуються м'яко: запис залишається в базі, а публічні endpoints повертають тільки активні бренди.

### Деактивація

```http
DELETE {{baseUrl}}/api/brands/{{brandId}}
Authorization: Bearer {{adminToken}}
```

Успішна відповідь — `200 OK` з повідомленням `Brand deactivated successfully.`. Якщо бренд не існує або вже деактивований, повертається `404 Not Found`.

Soft delete не видаляє сам запис бренду і не обнуляє `BrandId` у товарах, оскільки рядок бренду фізично не видаляється. Публічний каталог не показує назву неактивного бренду, а фільтрація товарів за цим брендом не повертає товари бренду, доки він неактивний.

### Відновлення

```http
POST {{baseUrl}}/api/brands/{{brandId}}/restore
Authorization: Bearer {{adminToken}}
```

Успішна відповідь — `200 OK` з повідомленням `Brand restored successfully.`. Якщо бренд відсутній або вже активний, повертається `404 Not Found`. Після відновлення бренд знову доступний у публічному каталозі.

## 6. Завантажити або замінити логотип бренду

Потрібен токен адміністратора. Файл передається через `multipart/form-data`.

```http
POST {{baseUrl}}/api/brands/{{brandId}}/logo
Authorization: Bearer {{adminToken}}
```

У Postman:

1. Виберіть метод `POST` і URL вище, замінивши `{{brandId}}` на ID активного бренду.
2. Відкрийте **Body → form-data**.
3. Додайте поле `file`, змініть його тип на **File** і виберіть зображення.
4. Додайте заголовок авторизації та надішліть запит.

Дозволені формати — JPEG, PNG і WEBP. Максимальний розмір файлу — 5 MiB, максимальний розмір зображення — 12 000 000 пікселів. Порожні файли та анімовані зображення не підтримуються. Сервер перевіряє MIME-тип і фактичний формат зображення, перевіряє розміри та нормалізує файл перед збереженням.

Приклад успішної відповіді:

```json
{
  "status": {
    "isOk": true,
    "code": 200,
    "message": "OK"
  },
  "meta": {
    "apiName": "BrandLogo",
    "dataType": "application/json",
    "manipulations": ["POST"],
    "links": {
      "parent": "/api/brands",
      "logo": "/api/brands/images/a1b2c3d4e5f678901234567890abcdef.webp"
    }
  },
  "data": {
    "brandId": "00000000-0000-0000-0000-000000000001",
    "logoKey": "a1b2c3d4e5f678901234567890abcdef.webp",
    "logoUrl": "/api/brands/images/a1b2c3d4e5f678901234567890abcdef.webp"
  }
}
```

Збережіть `logoKey` або повторно отримайте бренд через `GET /api/brands/{id}` — у полі `logoUrl` буде шлях для перегляду логотипа.

Повторне завантаження замінює логотип бренду. Після успішного збереження нового ключа в базі сервер намагається видалити попередній локальний файл. Якщо бренд не існує або деактивований, endpoint повертає `404 Not Found` і намагається прибрати щойно завантажений файл. Якщо файл відсутній, порожній або не пройшов перевірку LocalStorage, повертається `400 Bad Request`.

## 7. Отримати файл логотипа

```http
GET {{baseUrl}}/api/brands/images/{{imageKey}}
```

Цей endpoint публічний і не потребує токена. `imageKey` — ключ, який повернув endpoint завантаження, наприклад `a1b2c3d4e5f678901234567890abcdef.webp`.

Успішний запит повертає байти зображення з відповідним MIME-типом, а не JSON. У браузері можна відкрити повну адресу логотипа; у Postman — переглянути або зберегти відповідь як файл.

Дозволені розширення: `.jpg`, `.png`, `.webp`. Непідтримуване розширення повертає `400 Bad Request`; некоректний ключ — `400 Bad Request`; якщо файл не знайдено — `404 Not Found`.

`logoUrl` у відповідях бренду є відносним шляхом до API, наприклад:

```text
/api/brands/images/a1b2c3d4e5f678901234567890abcdef.webp
```

Якщо frontend працює на іншому домені або порту, додайте перед цим шляхом базову адресу API.
